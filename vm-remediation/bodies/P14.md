# [Intel Mac P14] Consolidate suspend diagnostics

Carry omacom/omarchy#11904’s standalone suspend diagnostics command with software recovery repairs. Failed restores remain retryable, privileged state is private and locked, interrupted diagnosis stops after restoration, failed sleep tests return failure, and existing rules are preserved. It adds no automatic boot, installer or sleep hook.

**Draft consolidation for source review and hardware-owner follow-up.** Known defects remain; no hardware or merge-readiness certification is claimed. Part of the [14-feature Intel Mac series](https://github.com/andrew-boyd/omarchy/blob/intel-mac/review-index/INTEL-MAC-ROLLUPS.md) with three package companions.

**Contribute:** open follow-up PRs in `andrew-boyd/omarchy` with base **`intel-mac/p14-suspend-diagnostics`**. Use `[Intel Mac P14]` in the title and a contributor branch such as `intel-mac/p14/describe-change`. Link this feature in the series index. Merging a follow-up into this branch updates its roll-up.

## Known gaps and follow-up work

- [ ] A complete physical Mac diagnose/recovery loop remains unverified. Virtual RTC sleep and controlled failure fixtures do not identify real wake sources.
- [ ] Generated USB rules still match vendor/product broadly. Wall-clock duration alone does not establish S3 or the cause of an early wake.
- [ ] Active commands suspend or change wake settings and require an attended recoverable hardware trial with independently captured state.
- [ ] The source’s repeated-suspend hardware risk and physical rollback questions remain; no new hardware policy is invented.
- [ ] Signal recovery is covered by controlled fixtures. RTC cancellation during an interrupted physical suspend and driver recovery afterward remain unverified.
